# 阶段三：搜索与文件

> 目标：把"搜索"和"文件"两个高频后端场景补上。
> 预估：1-2 周
> 依赖：阶段一、阶段二

---

## 一、阶段目标

- Elasticsearch：全文搜索、分词、高亮、聚合。
- MySQL ↔ ES 数据同步的常见套路（先双写，再引出 canal / MQ）。
- MinIO：对象存储上传下载、预签名 URL、文件元信息表。

---

## 二、准备工作：环境

`docker-compose.dev.yml` 追加：

```yaml
  elasticsearch:
    image: elasticsearch:7.17.10
    environment:
      - discovery.type=single-node
      - ES_JAVA_OPTS=-Xms512m -Xmx512m

  kibana:
    image: kibana:7.17.10
    ports: ["5601:5601"]

      - ELASTICSEARCH_HOSTS=http://elasticsearch:9200

    image: minio/minio
    command: server /data --console-address ":9001"
    ports: ["9000:9000", "9001:9001"]
    environment:
      MINIO_ROOT_USER: admin
      MINIO_ROOT_PASSWORD: admin12345
```

### 3.2 双写：MySQL ↔ ES

## 六、常见坑

- **ES 分词不生效**：字段类型必须是 `text`，`keyword` 不分词。
- **索引 mapping 后不能改字段类型**：设计时想清楚，改字段要 reindex。
- **双写不一致**：DB 提交后再写 ES；ES 写失败要能补偿（MQ / 定时任务）。
- **MinIO 预签名 URL 过期时间**：太短前端加载失败，太长有泄露风险，一般 1 小时。
- **上传前端跨域**：MinIO 要配 CORS。
- **文件大小限制**：Spring `spring.servlet.multipart.max-file-size` 默认 1MB。
