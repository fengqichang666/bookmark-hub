### 4.7 集群下的推送问题

单机推送很简单，多机就麻烦：用户 B 连的 node1，通知消息在 node2 消费，node2 不知道 B 在哪。

- [ ] **7.1** 方案 A：所有 node 订阅 Redis Pub/Sub 广播，每个 node 只推给自己持有的 session。
- [ ] **7.2** 方案 B：用 MQ 广播。
- [ ] **7.3** 至少写一个方案，理解"有状态服务的粘性问题"。

**验收**：跑两个后端实例（不同端口），任意一个消费 MQ 都能推给正确用户。

## 五、常见坑

- **权限缓存不刷新**：改角色 / 改权限后忘删缓存，用户越权。
- **JWT 里塞角色**：角色改了 token 里的还在生效。角色不塞、权限也不塞，实时查。
- **WebSocket 鉴权**：不能像 HTTP 那样加 header，一般把 token 放 query 参数或第一条消息里。
- **Session 泄漏**：客户端断了没触发 `onClose`（心跳丢失），要主动清 idle session。
- **邮件发送阻塞接口**：一定要走 MQ 异步，不然邮件服务挂了业务全挂。
