# 阶段五：可观测与治理（可选进阶）

> 目标：把"生产级"的观测、追踪、日志、部署配齐。
> 预估：1-2 周
> 依赖：前面四个阶段
> **注意：这个阶段偏运维和 SRE，学到就是赚到，不做也不影响面试。**

---

## 一、阶段目标

- 监控：Prometheus + Grafana 看指标。
- 追踪：SkyWalking 看调用链。
- 日志：ELK / Loki 集中化。
- 部署：Docker Compose 一键起。
- 进阶：拆微服务、上 Nacos / Gateway。

---

## 二、任务清单

### 5.1 Actuator + Prometheus

- [ ] **1.1** 引入 `spring-boot-starter-actuator` + `micrometer-registry-prometheus`。
- [ ] **1.2** 暴露 `/actuator/prometheus`。
- [ ] **1.3** `docker-compose` 加 prometheus，抓取应用指标。
- [ ] **1.4** 自定义业务指标：
  ```java
  meterRegistry.counter("bookmark.create.count").increment();
  Timer.Sample sample = Timer.start(meterRegistry);
  // ...
  sample.stop(meterRegistry.timer("bookmark.enrich.duration"));
  ```

**验收**：Prometheus 里能查到 JVM、接口 QPS、自定义业务计数器。

---

### 5.2 Grafana 大盘

- [ ] **2.1** `docker-compose` 加 grafana。
- [ ] **2.2** 导入 JVM 大盘（模板 ID 4701）。
- [ ] **2.3** 自建业务大盘：书签新增速率、抓取平均耗时、MQ 积压、Redis 命中率。
- [ ] **2.4** 配告警：QPS 超阈值、慢接口、失败率。

**验收**：Grafana 里能看到 JVM 曲线 + 业务曲线，触发告警能出邮件。

---

### 5.3 SkyWalking 链路追踪

- [ ] **3.1** 起 SkyWalking OAP + UI。
- [ ] **3.2** 应用启动加 javaagent：
  ```
  -javaagent:/path/to/skywalking-agent.jar
  -Dskywalking.agent.service_name=bookmark-hub
  -Dskywalking.collector.backend_service=localhost:11800
  ```
- [ ] **3.3** 打开一个慢接口，在 SkyWalking UI 里看整条链路（HTTP → Service → MyBatis → Redis → MQ）。

**验收**：能定位一次慢请求慢在哪一步。

---

### 5.4 日志集中化

选一个方案：

**方案 A：ELK**
- [ ] **4.1** logback 配 JSON 格式输出（`logstash-logback-encoder`）。
- [ ] **4.2** Filebeat 采集 → Logstash → Elasticsearch。
- [ ] **4.3** Kibana 建 Dashboard，按 traceId 检索。

**方案 B：Loki（更轻量）**
- [ ] **4.4** Promtail 采集 → Loki。
- [ ] **4.5** Grafana 里直接查日志。

- [ ] **4.6** **traceId 贯穿**：MDC 里放 traceId（SkyWalking 会自动注入），所有日志带 traceId，一条链路能串起来。

**验收**：给一个 traceId，能查到该请求的所有日志（应用日志、MQ 消费日志、异步任务日志）。

---

### 5.5 健康检查 + 优雅停机

- [ ] **5.1** `/actuator/health` 自定义 indicator：
  - Redis 通不通
  - MQ 通不通
  - ES 通不通
- [ ] **5.2** 配 `server.shutdown=graceful`，`spring.lifecycle.timeout-per-shutdown-phase=30s`。
- [ ] **5.3** 停机时：
  - 停止接受新请求
  - 等待正在处理的请求完成
  - MQ 消费者优雅关闭
  - 关连接池

**验收**：`docker stop` 后 30s 内能看到 "正在处理 N 个请求" 的日志，都处理完才退出。

## 四、这一阶段的价值

前面四阶段做完，你已经"会写"了。这一阶段做完，你能"讲清楚生产上怎么跑"。

## 五、常见坑

- **Prometheus 抓取路径要开权限**：Actuator 默认只暴露 health/info，`management.endpoints.web.exposure.include=*` 别忘。
- **SkyWalking agent 版本必须匹配 OAP**：不然连不上。
- **日志字段爆炸**：JSON 日志字段太自由，ES mapping 容易爆，规范字段名。
- **优雅停机等太久**：设个上限，不能无限等。
- **微服务拆早**：单体阶段没跑通就拆微服务，纯给自己找罪受。
